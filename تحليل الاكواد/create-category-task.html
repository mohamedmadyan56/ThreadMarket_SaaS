تاسك Create Category — الشرح الكامل + الكود خطوة بخطوة

ThreadMarket SaaS — شرح تاسك جيرا + تنفيذ كامل بالكود، متناسق مع الـ module الموجود في المشروع فعلاً.

1) شرح التاسك نفسه (Task Overview)

التاسك عبارة عن Endpoint جديد لإنشاء كاتيجوري (تصنيف) جديد وربطه ببراند معين. يعني البراند بيقدر يضيف تصنيفات خاصة بيه للمنتجات بتاعته.

المعلومةالتفاصيل
HTTP MethodPOST
Endpoint/brands/{brandId}/categories
Descriptionإنشاء كاتيجوري جديدة
Authentication Requiredنعم (Bearer Token)
Authorized Rolesbrand فقط
Request Bodyname (مطلوب: string) + imageUrl (اختياري: string)
Validation Ruleاسم الكاتيجوري لازم يكون فريد داخل البراند الواحد
Success Response201 مع { success, message, data: { id } }
Error ResponsesValidation Error (400) / Forbidden (403) / Internal Server Error (500)

مثال الـ Request من التاسك:

POST /brands/<brandId>/categories
Authorization: Bearer <token>

{
  "name": "Women's Wear",
  "imageUrl": "https://cdn.example.com/category.png"
}

الـ Response المتوقع:

{
  "success": true,
  "message": "Category created successfully",
  "data": { "id": "uuid" }
}

الـ Business Logic:

  • إنشاء الكاتيجوري وربطها بالبراند (brandId).
  • Side effects: none — مفيش حاجة تانية بتتغير في النظام.
نقطة مهمة هتفرق في الكود: التاسك بيقول الـ endpoint هو /brands/{brandId}/categories. في المشروع، الـ brandRouter مركّب على /api/v1/brands في server.ts:27. يعني أحسن مكان للـ route ده هو ملف brand.routes.ts عشان الـ URL يطلع صح بالظبط زي التاسك. لو حطيناه في category.routes.ts (المركّب على /api/v1/categories) هيطلع POST /api/v1/categories/:brandId/categories — شكل وحش ومش زي التاسك.

2) المشروع والمشكلة المهمة في الـ Data Model أولاً 🚨

قبل ما نكتب أي كود، لازم نفهم حالة الـ Category في المشروع. فيه تعارض لازم نعرفه:

تعارض بين الـ schema و الـ client المولّد:
  • الـ prisma/schema.prisma الحالي (المفروض يمثل الداتابيز) عنده: name @unique + description + مفيش brandId.
  • لكن الـ src/generated/prisma/models/Category.ts (الـ client المولّد اللي بيشتغل به الكود فعلاً) عنده: brandId + imageUrl + relation brand + unique مركب brandId_name + مفيش description.
  • يعني الـ client المولّد متولّد من schema أحدث من الموجود في الملف، والملف الحالي متأخر عنه.

عشان التاسك يقول "Create category and link it to the brand" + "name must be unique within the brand"، فالموديل الصح هو اللي فيه brandId — وده اللي الـ client بيدعمه. فقبل ما نكتب الكود، لازم نحدّث الـ schema في prisma/schema.prisma عشان يطابق اللي الكود هيستخدمه:

تحديث prisma/schema.prisma — موديل Category الصحيح

model Category {
  id          String    @id @default(uuid()) @db.Uuid
  brandId     String    @map("brand_id") @db.Uuid
  name        String    @map("category_name")
  imageUrl    String?   @map("image_url")
  media       Json
  ishidden    Boolean   @default(false)
  Products    Product[]
  brand       Brand     @relation(fields: [brandId], references: [id], onDelete: Cascade)
  createdAt   DateTime  @default(now())
  updateAt    DateTime  @default(now())

  @@unique([brandId, name])   // نفس الاسم ممنوع يتكرر لنفس البراند — دي قاعدة التاسك
  @@map("categories")
}
وبعدها تشغّل: npx prisma generate ثم npx prisma migrate dev --name create_category_v2 عشان الجدول في الداتابيز يتحدث مع الـ client. (لو الـ client المولّد عندك ناقص عن ده، الـ generate هيجيله.)

ملحوظة على الحقول اللي مش في التاسك: media حقل Json مطلوب في الـ schema، فهنمررله {}. و ishidden عنده default false فمش محتاجين نمرره.

تعديل src/modules/category/category.model.ts — دالة الـ create

نضيف دالة findByNameWithinBrand (عشان نتأكد من قاعدة الـ uniqueness قبل الإنشاء) ودالة create:

import prisma from "../../config/database";

class categoryModel {
  // (جديد) فحص تكرار الاسم جوه البراند — قاعدة التاسك
  async findByNameWithinBrand(brandId: string, name: string) {
    return prisma.category.findFirst({
      where: { brandId, name },
      select: { id: true },
    });
  }

  // (جديد) إنشاء كاتيجوري مرتبطة بالبراند
  async create(brandId: string, name: string, imageUrl?: string) {
    return prisma.category.create({
      data: {
        brandId,                          // الربط بالبراند
        name,
        media: {},                        // Json مطلوب في الـ schema
        ...(imageUrl ? { imageUrl } : {}), // اختياري: نحطه بس لو اتبعت
      },
      select: { id: true },               // نرجع الـ id بس زي التاسك
    });
  }

  // موجودة قبل كده (بتاعة الـ getCategories)
  async getCategories(filter: { search: string; skip?: number; take?: number }) {
    return await prisma.category.findMany({ /* ... */ });
  }
}

export const category = new categoryModel();

شرح:

  • findByNameWithinBrand: لو رجع نتيجة → الاسم موجود لنفس البراند → لازم نمنع الإنشاء (دي قاعدة التاسك).
  • create: بنمرر brandId في الـ data مباشرة — ده هو "Create category and link it to the brand" حرفيًا.
  • استخدمنا ...(imageUrl ? { imageUrl } : {}) لأن الـ imageUrl اختياري — لو مش متبعت، الحقل ميتكتبش.
  • باستخدام select: { id: true } بناخد بس الـ id اللي التاسك طالبه في الـ response.

تعديل src/modules/category/category.service.ts — الـ Business Logic

نضيف ميثود createCategory وفيها كل القرارات والأخطاء:

import { category } from "./category.model";
import { brandModel } from "../brand/brand.model";
import AppError from "../../shared/errors/AppError";
import { StatusCodes } from "http-status-codes";

class CategoryService {
  // (جديد) إنشاء كاتيجوري
  async createCategory(brandId: string, userId: string, role: string, name: string, imageUrl?: string) {
    // 1) البراند موجود؟
    const brand = await brandModel.findBrandById(brandId);
    if (!brand) {
      throw new AppError("Brand not found", StatusCodes.NOT_FOUND);
    }

    // 2) المستخدم صاحب البراند ده أو admin؟
    if (brand.userId !== userId && role !== "admin") {
      throw new AppError(
        "You are not authorized to create a category for this brand",
        StatusCodes.FORBIDDEN,
      );
    }

    // 3) الاسم فريد جوه البراند؟ (قاعدة التاسك)
    const existing = await category.findByNameWithinBrand(brandId, name);
    if (existing) {
      throw new AppError(
        "Category name already exists in this brand",
        StatusCodes.CONFLICT,
      );
    }

    // 4) الإنشاء الفعلي
    const created = await category.create(brandId, name, imageUrl);
    if (!created) {
      throw new AppError(
        "Category creation failed",
        StatusCodes.INTERNAL_SERVER_ERROR,
      );
    }

    return { id: created.id };
  }

  // موجودة قبل كده
  async getCategories(filter: { search: string; skip?: number; take?: number }) {
    return await category.getCategories(filter);
  }
}

export const categoryService = new CategoryService();

شرح كل خطوة:

  • الخطوة 1: لو الـ brandId مبيشاور على براند موجود → 404 Not Found.
  • الخطوة 2: تأكيد الملكية — بنقارن brand.userId بالـ userId الجاي من الـ token، وبنسمح للـ admin. نفس النمط بالظبط المستخدم في brand.service.ts:92 و brand.service.ts:167. لو مش مالك → 403 Forbidden. دي أساسية لأن الـ authorize middleware بيأكد "الـ role brand" بس، لكن مش بيأكد "ده البراند بتاعك".
  • الخطوة 3: قبل الإنشاء بنفحص الـ uniqueness — لو الاسم موجود لنفس البراند → 409 Conflict. دي قاعدة التاسك بالظبط.
  • الخطوة 4: إنشاء + لو حصل فشل غريب → 500 Internal Server Error (زي ما التاسك طالب في الـ Error Responses).
ليه بنفحص الـ uniqueness يدويًا رغم وجود @@unique([brandId, name])؟ الـ constraint في الداتابيز حماية أمان (شبكة أمان)، لكن لو اتخبطنا فيه هنجيب خطأ Prisma خام (P2002) مش هيكون له شكل لطيف. الفحص اليدوي بيدينا رسالة واضحة + 409 Conflict بطريقة نظيفة. الأثنين ماشيين مع بعض.

تعديل src/modules/category/category.controller.ts — الـ Controller

نضيف الـ controller اللي بياخد الـ params والـ body ويستدعي الـ service:

import { Request, Response } from "express";
import { StatusCodes } from "http-status-codes";
import { asyncHandler } from "../../shared/utils/asyncHandler";
import { categoryService } from "./category.service";
import AppError from "../../shared/errors/AppError";

// (جديد) إنشاء كاتيجوري
export const createCategory = asyncHandler(async (req: Request, res: Response) => {
  const { brandId } = req.params as { brandId: string };
  const { name, imageUrl } = req.body as { name: string; imageUrl?: string };
  const user = (req as any).user;

  if (!user?.id) {
    throw new AppError("Not authenticated", StatusCodes.UNAUTHORIZED);
  }

  const result = await categoryService.createCategory(
    brandId,
    user.id,
    user.role,
    name,
    imageUrl,
  );

  res.status(StatusCodes.CREATED).json({
    success: true,
    message: "Category created successfully",
    data: result,
  });
});

export const getCategories = asyncHandler(async (req: Request, res: Response) => { /* ... */ });

شرح:

  • brandId جاي من الـ req.params (جزء من الـ URL).
  • name و imageUrl جايين من req.body.
  • الـ user جاي من الـ authenticate middleware اللي حطه في req.user.
  • الـ Response: 201 Created بنفس الـ shape المطلوب في التاسك بالظبط.

كتابة src/modules/category/category.validators.ts — الـ Validation بـ Zod

الملف ده كان فاضي — ده أول كود فيه. بنستخدم validate middleware اللي موجود في src/shared/middleware/validate.ts واللي بيدمج body + query + params كلهم في schema واحد:

import { z } from "zod";

export const createCategorySchema = z.object({
  brandId: z.string().uuid({ message: "Invalid brand ID format" }),
  name: z
    .string()
    .min(1, "Category name is required")
    .max(50, "Category name must be at most 50 characters"),
  imageUrl: z.string().url("Invalid image URL format").optional(),
});

شرح:

  • brandId: مش في الـ body — في الـ URL، لكن لأن الـ validate بيمرج الـ params مع الباقي، فبيدخل في نفس الـ schema (بمطابقة uuid).
  • name: مطلوب وغير فاضي (زي التاسك).
  • imageUrl: اختياري + لازم يكون URL صحيح.
  • لو أي حاجة غلط → الـ middleware بيرمي 400 Validation Error بأول رسالة.

تعديل src/modules/brand/brand.routes.ts — تسجيل الـ Route

هنا بنضيف الـ route الجديد داخل ملف الـ brand routes عشان الـ URL يطابق التاسك (/api/v1/brands/:brandId/categories):

import { Router } from "express";
import { validate } from "../../shared/middleware/validate";
import authenticate from "../../shared/middleware/authenticate";
import { authorize } from "../../shared/middleware/authorize";
import { createBrand, updateBrandProfile, /* ... */ } from "./brand.controller";
import { createBrandSchema, updateBrandProfileSchema, /* ... */ } from "./brand.validators";
// استيراد من موديول الكاتيجوري
import { createCategory } from "../category/category.controller";
import { createCategorySchema } from "../category/category.validators";

const router = Router();
router.use(authenticate);

// ... الـ routes القديمة موجودة هنا ...

// (جديد) إنشاء كاتيجوري داخل براند — بيطابق POST /brands/{brandId}/categories
router.post(
  "/:brandId/categories",
  authorize("brand"),
  validate(createCategorySchema),
  createCategory,
);

export default router;
ترتيب الـ middlewares مهم:
  1. authenticate شغال على كل الـ file بـ router.use (مش محتاج نعيده).
  2. authorize("brand"): يرفض أي حد مش براند بـ 403.
  3. validate(createCategorySchema): تحقق من المدخلات بـ 400.
  4. createCategory: الـ controller بيكمل.

تأكد إن الـ category module و الـ brand module مترابطين صح

الـ category.service.ts بيستورد brandModel من ../brand/brand.model — وده موجود فعلًا ومستدعي في brand.service.ts كمان، فهيعمل import عادي من غير أي Circular dependency.

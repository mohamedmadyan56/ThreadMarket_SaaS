تاسك Update Category — الشرح الكامل خطوة بخطوة

ThreadMarket SaaS — التاسك مكتوب على Jira، وهنا هنشرح التاسك نفسه + تنفيذ الكود الكامل على أرض الواقع في المشروع.

1) شرح التاسك نفسه (Task Overview)

التاسك عبارة عن Endpoint جديد لتعديل (Update) كاتيجوري موجودة بتاعة براند معين. يعني كل براند له مجموعة categories، وده الـ endpoint اللي بيسمح له يعدّل أي كاتيجوري من بتوعه.

المعلومةالتفاصيل
HTTP MethodPATCH
Endpoint/brands/{brandId}/categories/{catId}
Authenticationمطلوب (Bearer Token)
Authorized Rolesbrand فقط (مع إمكانية admin)
Path ParametersbrandId + catId
Request Bodyجزء من بيانات الكاتيجوري (partial) — يعني ممكن ترسل اسم بس أو صورة بس
Success Response200 مع { success, message, data }
Error ResponsesValidation Error (400) / Not Found (404) / Forbidden (403)

الـ Business Logic المطلوب:

  • الكاتيجوري لازم تكون بتاعة البراند ده فعلاً (التأكد إن catId.brandId === brandId).
  • لو مش بتاعته → Forbidden أو Not Found.
  • Side effects: none (مفيش حاجة تتغير غير الكاتيجوري نفسها).
ليه بنستخدم PATCH مش PUT؟ لأن الـ PATCH يعني "تعديل جزئي" — بنسمح للمستخدم يبعت بس الحقول اللي عايز يعدلها، أما PUT فبيتوقع إنك تبعت الكيان كامل. التاسك بيقول "partial category payload" فده PATCH بالظبط.

3) الـ Data Model (schema.prisma) — شكل الكاتيجوري في الداتابيز

model Category {
  id        String    @id @default(uuid()) @db.Uuid
  brandId   String    @map("brand_id") @db.Uuid
  name      String    @map("category_name")
  imageUrl  String?   @map("image_url")
  media     Json
  ishidden  Boolean   @default(false)
  Products  Product[]
  createdAt DateTime  @default(now())
  updateAt  DateTime  @default(now())
  brand Brand @relation(fields: [brandId], references: [id], onDelete: Cascade)

  @@unique([brandId, name])   // نفس الاسم ممنوع يتكرر لنفس البراند
  @@map("categories")
}

الحقول اللي ممكن نعدّلها في التاسك ده: name و imageUrl و ishidden. الـ brandId ممنوع يتغير (الكاتيجوري مش هتتحول لبراند تاني).

نقطة الانتباه: جدول Category فيه @@unique([brandId, name]) — يعني لو حبيت تعدّل الاسم، لازم نتأكد إن الاسم الجديد مش متاخد من كاتيجوري تانية لنفس البراند، وإلا هنشيل خطأ Conflict من الداتابيز نفسه. الـ service هيتعامل مع ده.

هنا هننفّذ الـ Update خطوة بخطوة، بنفس نمط الـ Create الموجود في المشروع. الترتيب: الـ Model → الـ Service → الـ Controller → الـ Validator → الـ Route.

تعديل src/modules/category/category.model.ts — إضافة دوال الداتابيز

نضيف دالة findByIdWithinBrand (للتأكد إن الكاتيجوري بتاعة البراند) ودالة update (للتعديل الفعلي):

import prisma from "../../config/database";

class CategoryModel {
    // موجودة قبل كده — لفحص تكرار الاسم
    async findByNameWithinBrand(brandId: string, name: string) {
        return prisma.category.findFirst({
            where: { brandId, name },
            select: { id: true },
        });
    }

    // (جديد) جلب كاتيجوري بشرط أنها تخص براند معين
    async findByIdWithinBrand(brandId: string, catId: string) {
        return prisma.category.findFirst({
            where: { id: catId, brandId },
        });
    }

    // (جديد) تعديل جزئي — بنبعت فقط الحقول اللي اتغيرت
    async update(catId: string, data: { name?: string; imageUrl?: string; ishidden?: boolean }) {
        return prisma.category.update({
            where: { id: catId },
            data: {
                ...(data.name !== undefined ? { name: data.name } : {}),
                ...(data.imageUrl !== undefined ? { imageUrl: data.imageUrl } : {}),
                ...(data.ishidden !== undefined ? { ishidden: data.ishidden } : {}),
                updateAt: new Date(),
            },
            select: { id: true },
        });
    }

    // موجودة قبل كده
    async create(brandId: string, name: string, imageUrl?: string) {
        return prisma.category.create({
            data: {
                brandId,
                name,
                media: {},
                ...(imageUrl ? { imageUrl } : {}),
            },
            select: { id: true },
        });
    }
}

export const categoryModel = new CategoryModel();

شرح كل جزء:

  • findByIdWithinBrand: بنستخدم findFirst بـ where: { id: catId, brandId } — ده هو التطبيق العملي لـ "Validation Rules: category must belong to the brand". لو رجع null يبقى الكاتيجوري مش موجودة أو مش بتاعة البراند ده.
  • update: في Prisma الـ update بيرمي خطأ لو الـ id مش موجود، وبنبني الـ data بشكل ديناميكي عشان نعدّل الحقول المبعوتة بس (partial update). updateAt: new Date() عشان نحدّث طابع الوقت.
  • استخدمنا spread مع check (...(... !== undefined ? {...} : {})) لأن كده لو المستخدم مبعتهاش حاجة، الحقل مش هيتعدل.

تعديل src/modules/category/category.service.ts — الـ Business Logic

نضيف ميثود updateCategory اللي فيها كل القرارات:

import AppError from "../../shared/errors/AppError";
import { StatusCodes } from "http-status-codes";
import { brandModel } from "../brand/brand.model";
import { categoryModel } from "./category.model";

class CategoryService {

    // موجودة قبل كده
    async createCategory(brandId, userId, role, name, imageUrl?) {
        // ... نفس اللي موجود
    }

    // (جديد) تعديل كاتيجوري
    async updateCategory(brandId: string, catId: string, userId: string, role: string, data: { name?: string; imageUrl?: string; ishidden?: boolean }) {
        // 1) نتأكد إن البراند موجود
        const brand = await brandModel.findBrandWithDocuments(brandId);
        if (!brand) {
            throw new AppError("Brand not found", StatusCodes.NOT_FOUND);
        }

        // 2) صلاحية: صاحب البراند أو admin بس
        if (brand.userId !== userId && role !== "admin") {
            throw new AppError("You are not authorized to update this category", StatusCodes.FORBIDDEN);
        }

        // 3) الكاتيجوري موجودة وبتاعة البراند ده؟
        const category = await categoryModel.findByIdWithinBrand(brandId, catId);
        if (!category) {
            throw new AppError("Category not found or does not belong to this brand", StatusCodes.NOT_FOUND);
        }

        // 4) لو المستخدم بيعدّل الاسم، نتأكد إنه مش مكرر لنفس البراند
        if (data.name && data.name !== category.name) {
            const existing = await categoryModel.findByNameWithinBrand(brandId, data.name);
            if (existing && existing.id !== catId) {
                throw new AppError("Category name already exists in this brand", StatusCodes.CONFLICT);
            }
        }

        // 5) التعديل الفعلي
        const updated = await categoryModel.update(catId, data);
        return { id: updated.id };
    }
}

export const categoryService = new CategoryService();

شرح كل خطوة في الـ service:

  • الخطوة 1: البراند نفسه لازم موجود — لو لأ → 404 Not Found.
  • الخطوة 2: التأكد إن المستخدم هو صاحب البراند أو admin → لو لأ → 403 Forbidden. ده اللي يطلبه التاسك في "Authorized Roles: brand".
  • الخطوة 3: ده أهم سطر في التاسك كله — بنستخدم findByIdWithinBrand اللي بيعمل شرط مزدوج (id + brandId) في query واحدة. كده بنتأكد إن الكاتيجوري موجودة وإنها بتاعة البراند ده في نفس الوقت → لو لأ → 404.
  • الخطوة 4: لو الاسم بيتعدل، بنتحقق إن مفيش كاتيجوري تانية لنفس البراند عندها نفس الاسم الجديد (except الكاتيجوري نفسها) → لو في → 409 Conflict. ده بيحمي الـ @@unique([brandId, name]) من الداتابيز.
  • الخطوة 5: بننادي الـ model اللي بيعمل الـ Prisma update ويرجع الـ id.

تعديل src/modules/category/category.controller.ts — الـ Request/Response

نضيف الـ controller اللي بياخد الـ params والـ body ويستدعي الـ service:

import { Request, Response } from "express";
import { categoryService } from "./category.service";
import { StatusCodes } from "http-status-codes";
import { asyncHandler } from "../../shared/utils/asyncHandler";
import AppError from "../../shared/errors/AppError";

export const createCategory = asyncHandler(async (req: Request, res: Response) => {
    // ... الموجود قبل كده
});

// (جديد) تعديل كاتيجوري
export const updateCategory = asyncHandler(async (req: Request, res: Response) => {
    const { brandId, catId } = req.params as { brandId: string; catId: string };
    const { name, imageUrl, ishidden } = req.body;
    const user = (req as any).user;

    if (!user?.id) {
        throw new AppError("Not authenticated", StatusCodes.UNAUTHORIZED);
    }

    const result = await categoryService.updateCategory(
        brandId, catId, user.id, user.role,
        { name, imageUrl, ishidden }
    );

    res.status(StatusCodes.OK).json({
        success: true,
        message: "Category updated successfully",
        data: result,
    });
});

شرح:

  • بنقرأ brandId و catId من req.params (عشان هما في الـ URL).
  • بنقرأ name, imageUrl, ishidden من الـ body — كلهم optional عشان "partial payload". لو المستخدم مبعتهاش حاجة هيبقوا undefined والـ service هيتجاهلهم.
  • الـ user جاي من الـ authenticate middleware اللي حطه في req.user.
  • الـ response: 200 OK بنفس شكل الـ JSON المطلوب في التاسك بالظبط.

تعديل src/modules/category/category.validators.ts — الـ Validation بـ Zod

نضيف schema للتعديل (كل الحقول optional لأنها partial):

import { z } from "zod";

export const createCategorySchema = z.object({
    brandId: z.string().uuid({ message: "Invalid brand ID format" }),
    name: z.string().min(1, "Category name is required"),
    imageUrl: z.string().url("Invalid image URL format").optional(),
});

// (جديد) Schema للتعديل الجزئي
export const updateCategorySchema = z.object({
    brandId: z.string().uuid({ message: "Invalid brand ID format" }),
    catId: z.string().uuid({ message: "Invalid category ID format" }),
    name: z.string().min(1, "Category name cannot be empty").optional(),
    imageUrl: z.string().url("Invalid image URL format").optional(),
    ishidden: z.boolean().optional(),
});

شرح:

  • الـ validate middleware في المشروع بيدمج req.params + req.body + req.query مع بعض، فبنضع brandId و catId (اللي جايين من الـ params) في نفس الـ schema.
  • .optional() على كل حقول الـ body عشان المستخدم ممكن يعدل حقل واحد بس — وده اللي قصده التاسك بـ "partial category payload".
  • لو حاجة غلط، الـ middleware هيرمي 400 Validation Error بأول رسالة خطأ.

تعديل src/modules/category/category.routes.ts — ربط كل حاجة

نضيف الـ route الجديد بالـ middlewares بالترتيب الصحيح:

import { Router } from "express";
import { validate } from "../../shared/middleware/validate";
import authenticate from "../../shared/middleware/authenticate";
import { authorize } from "../../shared/middleware/authorize";
import { createCategory, updateCategory } from "./category.controller";
import { createCategorySchema, updateCategorySchema } from "./category.validators";

const router = Router();

router.post("/:brandId/categories",
    authenticate,
    authorize("brand"),
    validate(createCategorySchema),
    createCategory,
);

// (جديد) تعديل كاتيجوري
router.patch("/:brandId/categories/:catId",
    authenticate,              // 1) لازم يكون عامل login
    authorize("brand"),        // 2) لازم الـ role يكون brand
    validate(updateCategorySchema), // 3) تحقق من المدخلات
    updateCategory,            // 4) الـ controller
);

export default router;

شرح ترتيب الـ middlewares:

#Middlewareبيأكد إيه؟
1authenticateفيش user؟ → لو لأ: 401 Unauthorized
2authorize("brand")الـ role بتاعته brand؟ → لو لأ: 403 Forbidden
3validate(updateCategorySchema)المدخلات صح؟ → لو لأ: 400 Validation Error
4updateCategoryالمنطق والرد: 200 أو 403/404
خلاصة الـ URL الكامل: PATCH /api/v1/brands/:brandId/categories/:catId — لإن الـ router مركّب على /api/v1/brands في server.ts.

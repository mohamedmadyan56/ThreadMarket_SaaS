1. أول حاجة: افهم المشروع اللي شغال فيه

المشروع ده اسمه Modular Monolith — يعني كل حاجة في سيرفر واحد بس، لكن مقسّمة على موديولات (كل موديول عبارة عن فولدر شغال على حاجة معينة). افتح فولدر src وشوف:

src/ ├── server.ts ← نقطة البداية (بيشغّل السيرفر ويركّب الروتس) ├── config/ │ ├── env.ts ← بيقرا الـ env (أسرار التطبيق) │ └── database.ts ← اتصال الـ Prisma بقاعدة البيانات ├── shared/ ← حاجات مشتركة بين كل الموديولات │ ├── middleware/ │ │ ├── authenticate.ts ← بيتحقق من الـ Token (مهم جدًا للتاسك ده) │ │ ├── authorize.ts ← بيسمح لأدوار معينة بس │ │ └── validate.ts ← بيشيك على البيانات بـ Zod │ └── errors/AppError.ts ← كلاس الخطأ الموحد └── modules/ ← الموديولات (كل واحد فولدر) ├── auth/ ← تسجيل + دخول + OTP + Tokens ├── brand/ ← البراندات └── user/ ← ⭐ هتنشئها إنت بنفسك للتاسك ده
مبدأ مهم: كل موديول بيتكوّن من نفس الـ 4 ملفات: *.model.ts (قاعدة البيانات) → *.service.ts (منطق الأعمال) → *.controller.ts (استقبال الطلب والرد) → *.routes.ts (الروتس). وده النمط اللي بنتبعه في كل الموديولات.

2. افهم الـ User Model في قاعدة البيانات

فتح الملف prisma/schema.prisma — كل مستخدم في الجدول User:

model User {
  id             String      @id @default(uuid())
  username       String
  phone          String?     @unique
  email          String      @unique
  role           Role        @default(user)   // enum: user, brand, admin, delievryC, courier
  password       String
  picture_url    String?
  otp            String?
  otp_expiration DateTime?
  otp_purpose    otpPurpose?
  isVerified     Boolean     @default(false)
  isBanned       Boolean     @default(false)
  refreshToken   String?
  created_At     DateTime    @default(now())
  updated_At     DateTime    @default(now())
  // ... وأعمدة تانية
}
خد بالك من 3 حاجات:
  • الـ Jira عايز name، بس الجدول فيه username — يبقى هنعمل mapping لما نرجع الرد.
  • الجدول فيه password وotp وrefreshToken — دي بيانات حساسة ممنوع نرجعها أبدًا. هنستخدم select عشان نجيب اللي محتاجينه بس.
  • role من نوع enum بقيم محددة (user, brand, admin, delievryC, courier).

3. افهم الـ Token بيوصل إزاي ليك

لما المستخدم يعمل Login، الـ سيرفر بيرجّع حاجتين:

  • accessToken → في الـ Response Body، والـ Frontend بيحطه في Header اسمه Authorization: Bearer ...
  • refreshToken → في httpOnly Cookie (عشان يجدد الـ accessToken لما يخلص).

الـ accessToken بيتولّد في src/modules/auth/token.service.ts من غير id بس:

generateAccessToken({ id: user.id })   // البايلواد فيه id المستخدم فقط
يعني لما الـ authenticate يعمل jwt.verify() على الـ Token، هيستخرج req.user = { id: user.id }. وعشان نجيب باقي بيانات المستخدم (الاسم، الإيميل...)، هنرجع لقاعدة البيانات بـ الـ id ده.

4. افهم الـ authenticate middleware (مهم جدًا)

المكان: src/shared/middleware/authenticate.ts. وظيفته: يقرا الـ Token من الـ Header، يتحقق منه، ولو سليم يحط req.user ويكمّل الطلب.

const authenticate = asyncHandler(async (req, _res, next) => {
  const token = req.headers.authorization?.split(" ")[1];  // ياخد الجزء التاني بعد "Bearer"
  if (!token) throw new AppError("No token provided", 401);

  try {
    const decoded = jwt.verify(token, ENV.ACCESS_TOKEN_SECRET!);
    (req as any).user = decoded;   // ← req.user = { id: "..." }
    next();
  } catch {
    throw new AppError("Invalid or expired token", 401);
  }
});
Bug لقيناه وإتصلّح (لازم تعرفه): السطر كان مكتوب split("")[1] مش split(" ")[1].
  • split("") → بيقطع السطر على كل حرف! يعني لو الـ Header Bearer abc هياخد الحرف الثاني a → الـ verify هيفشل.
  • split(" ") → بيقطع على المسافة ويعطي ["Bearer", "abc"]، فناخد [1] = abc وهو الـ Token الحقيقي. ✅
لو الـ bug ده موجود، أي endpoint محمي هيبوظ. متنساش.

5. رحلة الطلب من الأول لآخر (افهم دي الأول)

1. Client → 2. GET /api/v1/users/me → 3. authenticate → 4. Controller → 5. Service → 6. Model → DB → 7. Response 200
  1. الـ Client يبعث الطلب ومعاه Authorization: Bearer <token>.
  2. الطلب يمر على authenticate اللي بيخزّن req.user = { id }.
  3. الـ Controller ياخد req.user.id وينادي الـ Service.
  4. الـ Service يستدعي الـ Model عشان يجيب بيانات المستخدم من DB.
  5. الـ Model يعمل Query آمنة (select) على prisma.user.
  6. لو مش موجود → 404. لو موجود → يرجع الـ 200 بالبروفايل.

الخطوة 3: user.model.ts — الجلب الآمن من قاعدة البيانات

يعمل Query بـ select عشان يرجع الحقول الآمنة بس (من غير password / otp / refreshToken).

import prisma from "../../config/database";

class UserModel {
  async findProfileById(id: string) {
    return prisma.user.findUnique({
      where: { id },
      select: {
        id: true,
        username: true,
        email: true,
        phone: true,
        role: true,
      },
    });
  }
}

export const userModel = new UserModel();
ليه select؟ لو سبتها من غير select، الـ findUnique هيرجع كل الأعمدة بما فيهم password وotp وrefreshToken — كارثة أمنية. الـ select بيدّينا اللي محتاجينه بس.

الخطوة 4: user.service.ts — منطق الأعمال

اللي بيمسك الـ Model، يعمل mapping، ويرمي 404 لو مش موجود.

import { userModel } from "./user.model";
import AppError from "../../shared/errors/AppError";
import { StatusCodes } from "http-status-codes";

class UserService {
  async getCurrentUser(userId: string) {
    const user = await userModel.findProfileById(userId);
    if (!user) throw new AppError("User not found", StatusCodes.NOT_FOUND);

    return {
      id: user.id,
      name: user.username,   // mapping: username في DB ← name في الرد
      email: user.email,
      phone: user.phone,
      role: user.role,
    };
  }
}

export const userService = new UserService();
ليه إعادة تشكيل الـ Object؟ جدول الـ DB فيه username، وجيرا عايز name. فبنرجّع object جديد بنفس شكل المواصفات بالظبط. ولو المستخدم اتوجدش، نرمي AppError بـ 404.

الخطوة 5: user.controller.ts — استقبال الطلب والرد

import { Request, Response } from "express";
import { userService } from "./user.service";
import { StatusCodes } from "http-status-codes";
import { asyncHandler } from "../../shared/utils/asyncHandler";
import AppError from "../../shared/errors/AppError";

export const getCurrentUser = asyncHandler(async (req: Request, res: Response) => {
  const userId = (req as any).user?.id;   // ← جاية من authenticate
  if (!userId) {
    throw new AppError("Not authenticated", StatusCodes.UNAUTHORIZED);
  }

  const profile = await userService.getCurrentUser(userId);

  res.status(StatusCodes.OK).json({
    success: true,
    message: "Profile retrieved successfully",
    data: profile,
  });
});
ليه asyncHandler؟ هو اختصار بيلفّ على الـ handler ويمسك أي error مرميّ داخله ويوصله للـ error handler في server.ts. من غيرها، أي throw هيتعلّق ويموت السيرفر.

الخطوة 6: user.routes.ts — الروت

الروت الوحيد GET /me مع authenticate (وبس — كل الأدوار مصرح بيها فمفيش authorize).

import { Router } from "express";
import authenticate from "../../shared/middleware/authenticate";
import { getCurrentUser } from "./user.controller";

const router = Router();

router.get("/me", authenticate, getCurrentUser);

export default router;

الخطوة 7: ركّب الروت في server.ts

افتح src/server.ts، أضف استيراد وسطر تركيب:

import userRouter from "./modules/user/user.routes";

app.use("/api/v1/auth", authRouter);
app.use("/api/v1/brands", brandRouter);
app.use("/api/v1/users", userRouter);   // ← الجديد
ليه الـ endpoint بقى /api/v1/users/me؟ لإن جيرا كتب /users/me والمشروع بيفضّل كل حاجة تحت /api/v1. فـ app.use("/api/v1/users", ...) + router.get("/me") = GET /api/v1/users/me.

7. التجربة (Postman)

  1. اعمل Login: POST http://localhost:4000/api/v1/auth/login ببيانات مستخدم موجود في الـ DB.
  2. خد الـ accessToken من الـ Response.
  3. اعمل Request جديد: GET http://localhost:4000/api/v1/users/me.
  4. في تبويب Authorization → اختار Bearer Token → الصق الـ Token.
  5. Send → يطلع 200 والبروفايل.

أو بـ curl:

curl -X GET http://localhost:4000/api/v1/users/me \
  -H "Authorization: Bearer <accessToken>"

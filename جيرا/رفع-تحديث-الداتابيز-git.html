شرح رفع تحديث قاعدة البيانات إلى GitHub

📘 إزاي ترفع تعديل الـ schema.prisma على البرانش الجديد

الخلاصة في سطرين: الداتابيز نفسها مش هتترفع على GitHub — هي عايشة على Neon. اللي هترفعه هو ملف prisma/schema.prisma (الوصفة). وده بيتم عبر: برانش جديد ← commit ← push.

0. أولاً: فهم مهم جدًا — الداتابيز دي فين؟

مشروعك (جهازك)↕Neon (سحابة)↕GitHub (code)

عندك 3 أماكن مختلفة، وكل واحد له دور:

المكانفيه إيه؟مين بيغيره؟
Neon (قاعدة البيانات)الجدوال والبيانات الفعليةإنت بتحط التعديل هنا بـ prisma db push
GitHub (المستودع)الكود + ملف schema.prismaهنا بترفع تعديلاتك عشان الفريق يشوفها
جهازك (local)نسخة من الكود + ملفات الـ configمن هنا بتكتب وبتشغّل الأوامر
المغزى: لما حد يسحب الكود من GitHub، مش بيجيب معاه بياناتك. هو بيجيب الـ schema.prisma وبعدين يعمل prisma db push عشان يبني لنفسه نفس الجداول. فرفع "التحديث" على GitHub = رفع تعديل السكيما.

1. إيه اللي عملته بالظبط لحد دلوقتي؟

تعديل الـ Category في السكيما (إضافة brandId + العلاقة العكسية) ثم:

npx prisma db push     # طبق التعديل على Neon ✅ (عملته)
npx prisma generate    # حدّث الـ Client ✅ (عملته)

دلوقتي الداتابيز الفعلية بتاعة Neon فيها الجداول الصح. اللي باقي هو رفع ملف schema.prisma على GitHub عشان الفريق يشوف التعديل.

2. الوضع الحالي بتاع الـ git (اللي شفناه في الملف السابق)

الملفالحالةشرح
prisma/schema.prismaM (Modified)✅ التعديل المهم — ده اللي عايز ترفعه
src/modules/user/*.ts (4 ملفات)Mتعديلات موديول الـ user — اختياري ترفعهم معاك
dist/** (كذا ملف)A (Staged)⚠️ ملفات البناء — مينفعش تترفع
src/modules/Category/?? (Untracked)ملفات فاضية لسه — مش متعمله
ملفات جيرا/*.html/pdf?? / Aمشروحات وـ PDFs — اختياري
الرموز: M = معدّل (Modified) | A = متضاف للـ staging (Added) | ?? = جديد مش متتابع (Untracked) | D = محذوف.

3. حاجة لازم نضبطها الأول: ملفات dist

ملفات dist/ هي ناتج الـ build (الـ tsc). إنت محتاجها عشان تشغّل المشروع بس، لكن مينفعش تتحط في الـ repo لأن:

  • بيتولّدوا من الكود — مفيش داعي تشاركهم.
  • بتتغير مع كل build → بتعمل تعارضات مزعجة في الـ merge.
  • بتكبّر حجم الـ repo بلا فايدة.

الحل — تضيفهم لملف الـ gitignore عشان git يهملهم نهائيًا:

# .gitignore
/node_modules
/src/generated/prisma
/.env
/مذاكره
/dist        # ← أضف السطر ده

4. خطوات الرفع بالترتيب (الأوامر)

الخطوة 1: اخلق البرانش الجديد

git checkout -b feature/createCategory

ده بيعمل برانش جديد من اللي إنت واقف عليه (main) وبينقلك عليه على طول. -b = Branch.

الخطوة 2: اشيل الـ dist من الـ staging

git reset dist/ # يشيلهم من الـ "semi ready" من غير ما يمسحهم

ملفات الـ dist هتفضل موجودة على جهازك — بس مش هتكون جاهزة تترفع.

الخطوة 3: عمِل stage للتعديلات المهمة

git add prisma/schema.prisma src/modules/user

ده بيقول لـ git: "الحاجات دي اللي عايز أرفعها". (السكيما + تعديلات الـ user).

الخطوة 4: اعمل commit

git commit -m "feat(category): add brand relation to category schema"

الـ commit = "صورة" محفوظة للتعديلات مع رسالة توصفها. الرسالة بتبدأ بـ feat للتعديلات الجديدة.

الخطوة 5: ارفع البرانش على GitHub

git push -u origin feature/createCategory

ده بيبعث البرانش (بكل الـ commits بتاعته) لـ GitHub. الـ -u بيسجّل البرانش كـ upstream عشان المرات الجاية تقدر تعمل git push بس.

5. شجرة الأوامر بالمصطلحات البسيطة

git add→git commit→git push
الأمرالتشبيهبيمس حاجة؟
git add"حط الأغراض في صندوق اللي هسافر"لأ
git commit"قفل الصندوق واكتب عليه وصف"لأ
git push"ابعت الصندوق لـ GitHub"لأ (بيضيف بس)
git reset"اطلع غرض من الصندوق"لأ — الملف نفسه بيفضل
git checkout -b"افتح خط شغل جديد"لأ

6. بعد ما ترفع — إيه اللي ييجي بعدها؟

  • هتحتاج تعمل Pull Request (PR) على GitHub — عشان تدمج البرانش في main.
  • غالبًا main عندكم مفتوح عليه بروتكشن، فمينفعش حد يدمج من غير مراجعة.
  • أي حد تاني يسحب البرانش ويشغّل prisma db push هياخد نفس تعديل الـ Category.

7. خلاصة القرارات اللي محتاج تاخدها

السؤالالخيار
ملفات الـ dist/؟شيلهم من الـ staging + ضيف /dist للـ gitignore — دي الصح
ملفات جيرا/؟ده قرارك — فيهم شرحك وملفاتك، تقدر ترفعهم أو تسيبهم خارج الـ git
تعديلات الـ user؟مش مربوطين بتاسك الـ category — أنضف تسيبهم على main أو برانش تاني، بس القرار لك
إزاي ترفع: ابدأ بتعديل الـ .gitignore، ثم git checkout -b feature/createCategory، ثم git reset dist/، ثم git add prisma/schema.prisma، ثم git commit، ثم git push -u origin feature/createCategory.

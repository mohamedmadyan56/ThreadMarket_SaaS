2. قاعدة البيانات — إزاي السكيما شايلة الفكرة؟

شوف الـ Category الموجود في prisma/schema.prisma (سطر 241):

model Category {
  id        String    @id @default(uuid()) @db.Uuid
  name      String    @unique @map("category_name")
  media     Json
  ishidden  Boolean   @default(false)
  Products  Product[]
  createdAt DateTime  @default(now())
  updateAt  DateTime  @default(now())
}
⚠️ المشكلة: الموديل ده مافيوش brandId — يعني القسم مش مرتبط بأي براند، والـ @unique على الاسم حاليًا على مستوى كل النظام (global) مش على مستوى البراند. التاسك عايز:
  • كل قسم يتربط ببراند واحد (علاقة Category → Brand).
  • الاسم يكون فريد ضمن البراند بس مش على مستوى العالم كله.

اللي محتاج تعمله في السكيما

model Category {
  id        String    @id @default(uuid()) @db.Uuid
  brandId   String    @map("brand_id") @db.Uuid
  name      String    @map("category_name")
  imageUrl  String?   @map("image_url")
  ishidden  Boolean   @default(false)
  Products  Product[]
  createdAt DateTime  @default(now())
  updateAt  DateTime  @default(now())

  brand Brand @relation(fields: [brandId], references: [id], onDelete: Cascade)

  @@unique([brandId, name])   // ← الاسم فريد ضمن البراند
  @@map("categories")
}
  • شلنا @unique من الاسم وحطيناه كـ @@unique([brandId, name]).
  • أضفنا brandId والعلاقة brand.
  • حوّلنا media (اللي كانت Json) لـ imageUrl String? عشان تناسب الحقل imageUrl المطلوب في التاسك.
وخد بالك: كمان محتاج تضيف categories Category[] في موديل Brand عشان العلاقة تكتمل من الطرفين.

قاعدة مهمة في Prisma: أي علاقة لازم تكون معرّفة من الطرفين — الطرف الأول (صاحب الـ FK) والطرف الثاني (الناحية اللي عندها الـ array). لو واحد بس ناقص، الـ validate هيفشل.

4. إزاي تحفظ التعديلات دي في قاعدة البيانات؟ (Migrations)

التعديل على schema.prisma لوحده مش كفاية — ده بس "الرسم". عشان الرسم ده يتحول لجدول فعلًا في قاعدة البيانات، محتاج migration. يعني الـ migration بيعمل:

schema.prisma→migration (ملف SQL)→PostgreSQL

سلسلة الأوامر كاملة (من الأهم للأهم):

npx prisma validate        # 1) تأكد إن السكيما سليمة (معملناه وعدّي ✅)
npx prisma migrate dev     # 2) يعمل migration ويعمل push للتغييرات + يعمل generate
npx prisma generate        # 3) يعمل تحديث للـ Prisma Client (أحيانًا الـ migrate بينفذها لوحده)
npx prisma migrate status  # (اختياري) يشوف مين migration مطبّق ومين لأ
ملاحظة على migrate dev: هيسألك تسمّي الـ migration — اكتب اسم وصفي بالـ English زي add_brand_relation_to_categories. وكمان هو بيرجّعلك generate أوتوماتيك، بس لو حسيت أن الـ Prisma Client لسه مش عارف الـ fields الجديدة، شغّل generate يدوي.

5. شرح العلاقة العكسية (Reverse Relation) بالتفصيل

علاقة الـ Category بالـ Brand هي علاقة One-to-Many: براند واحد → كذا قسم. وأي علاقة كده ليها ناحيتين في Prisma:

الناحيةفينالسبب
brand Brand @relation(...)في Categoryدي الناحية "المفصّلة" — فيها الـ brandId الفعلي (ForeignKey) اللي بيتخزن في جدول الـ categories
categories Category[]في Brandدي الناحية "المعاكسة" — مش بتخزن حاجة فعلًا، دي بس بتقول Prisma إنه من البراند تقدر توصل لأقسامه: prisma.brand.findUnique({ include: { categories: true } })
لماذا لازم الناحيتين؟ عشان Prisma تبقى عارفة إن الحقلين دول بيربطوا بعض. من غير الناحية التانية بتطلع: missing an opposite relation field. زي علاقة بالعقل: لو قلت "الوالد عنده أبناء" ولازم تذكر إن "الابن عنده أب" — الاثنين يوصفوا نفس العلاقة.

لاحظ كمان الـ onDelete: Cascade: يعني لو البراند اتشال من قاعدة البيانات، كل أقسامه هتتشال معاه أوتوماتيك — مفيش أقسام يتيمة.

هل categories Category[] معناها علاقة One-to-Many؟ — أيوه ✅

أيوه، بالظبط. العلاقة one-to-many بتتكون من ناحيتين في Prisma، ودي القاعدة البسيطة:

الناحيةالكودالمعنى
الطرف "الواحد" (Brand)categories Category[]البراند الواحد → كذا قسم
الطرف "المتعدد" (Category)brand Brandكل قسم → براند واحد
  • اللي عنده [] = الطرف "الواحد" في العلاقة (بيحوي كذا عنصر).
  • اللي من غير [] = الطرف "المتعدد" (كل عنصر بيمتلك واحد بس).
  • في قاعدة البيانات، المفتاح الأجنبي brandId بيتخزن في جدول الـ categories (طرف الـ many) مش في جدول الـ brands.

مثال واقعي: براند "Zara" عنده categories = [رجالي, حريمي, إكسسوارات]، وكل قسم من دول بيشاور على Zara بحقل brand. دي علاقة one-to-many كاملة.

6. خطوات التنفيذ بالترتيب

  1. 1عدّل السكيما: أضف brandId + علاقة brand في Category و categories في Brand، واعمل @@unique([brandId, name]). ثم npx prisma migrate dev.
  2. 2حضر الـ validator: باستخدام zod — brandId من الـ params لازم uuid، والـ body فيه name إجباري (string غير فاضي) و imageUrl اختياري (URL صالح).
  3. 3اعمل الـ model: طريقة createCategory(brandId, name, imageUrl) تستدعي prisma.category.create.
  4. 4اعمل الـ service:
    • تأكد إن البراند موجود (إلا 404).
    • تأكد إن req.user هو صاحب البراند (إلا 403).
    • اعمل findFirst على { brandId, name } — لو لقيته، اعمل throw بـ 409 "Category name already exists".
    • أنشئ القسم وارجع id.
  5. 5اعمل الـ controller: استخدم asyncHandler زي باقي المشروع، ورجع res.status(201).json({ success: true, message: "Category created successfully", data: { id } }).
  6. 6اعمل الـ routes: POST /:brandId/categories مع authenticate → authorize("brand") → validate(schema) → controller.
  7. 7ركّب الراوت: في server.ts تحت /api/v1/brands.
